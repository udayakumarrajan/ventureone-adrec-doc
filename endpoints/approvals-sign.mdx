---
title: "Request ADREC's signature"
description: "VentureOne sends the Title Safe transaction; ADREC's verifier checks it and signs with key 1."
---

```http
POST /approvals/{approvalId}/signatures
```

**Platform token only.** VentureOne sends the Title Safe transaction it built for an `APPROVED` request. ADREC's **verifier** recomputes the Safe transaction hash itself, reads the Safe and the Title Token from **ADREC's own node**, and runs every check below. Only if all pass does key 1 sign, through ADREC's custody.

<Warning>
  A signer sees only a hash, which says nothing about what the transaction does. The verifier is what stops ADREC signing, for example, a transaction that makes VentureOne the Title Safe's only owner. It must run on ADREC's side. See [Recommendations](/introduction/dual-token-recommendations).
</Warning>

## Body

| Field | Type | Req. | Use |
| --- | --- | --- | --- |
| `safe` | address | **REQUIRED** | The Title Safe |
| `safeTx` | object | **REQUIRED** | The Safe transaction, Safe field names: `to`, `value`, `data`, `operation`, `safeTxGas`, `baseGas`, `gasPrice`, `gasToken`, `refundReceiver`, `nonce` |
| `safeTxHash` | string | **REQUIRED** | The hash VentureOne expects. ADREC recomputes it and refuses a mismatch |
| `allocations[]` | object[] | OPTIONAL | An issuance minted in batches: the allocations this transaction mints (`wallet`, `units` in whole tokens). Each must be in the approval, with exactly its approved units, and not minted by an earlier batch. Omitted, the transaction mints every allocation still to mint |

<Info>
  **One approval, minted in batches.** A Safe transaction carries only so many mints (the network's gas limit per transaction), so a raise with more investors is minted in several transactions. The officer approves the whole raise once; VentureOne then sends one transaction per batch, each checked and co-signed under that approval.
</Info>

## The verifier's checks

Every check is recorded in ADREC's [audit trail](/endpoints/approvals-audit), passed or failed.

| Check | Refuses when |
| --- | --- |
| `approval_is_approved` / `approval_not_expired` | The request is not `APPROVED`, or its minting window (`mintBy`) has closed |
| `batch_is_part_of_the_approval` | The named batch has a wallet not in the approval, a different amount, a wallet twice, or a wallet an earlier batch minted |
| `nonce_replaces_the_signed_transaction` | A transaction signed under the approval was replaced before it executed, and this one is not at that Safe nonce |
| `hash_recomputed` | ADREC's own hash of `safeTx` differs from `safeTxHash` |
| `safe_is_the_approved_title_safe` | `safe` is not the Title Safe the request names |
| `safe_deployed` | No Safe at that address on ADREC's node |
| `adrec_key1_is_owner` / `threshold_needs_two` | ADREC key 1 is not an owner, or the threshold is below 2 |
| `no_quorum_without_adrec` | Owners other than ADREC's keys could reach the threshold |
| `no_modules` / `no_guard` | The Safe has a module or a guard that could act around the owners |
| `nonce_is_next` | The transaction is not at the Safe's next nonce |
| `no_gas_refund` / `no_eth` / `no_eth_in_calls` | Any gas refund or ETH moves |
| `batch_structure` | The batch is not the expected whitelist → mints → whitelist reset |
| `only_the_title_token` / `no_call_to_the_safe` | A call targets anything but the Title Token, or the Safe itself |
| `functions_allowed` | A call uses a function outside ADREC's allowlist |
| `matches_approved_content` | The wallets or amounts differ from what the officer approved for this transaction: its batch, or everything still to mint (each mint must be `units × 10^decimals`) |
| `decimals_are_the_title_tokens` | The Title Token's `decimals()` is not the `decimals` the request was filed with |
| `title_deed_anchored` | The Title Token's `documentUri()` is not the approved deed's anchor |

## Response

| `state` | Meaning |
| --- | --- |
| `SIGNED` | Every check passed; `signature` carries key 1's signature |
| `SIGNING` | ADREC's custody is still approving; poll [`GET /approvals/{approvalId}`](/endpoints/approvals-read) |

A failed check answers `1000` with the check's name in `responseMessage`, and nothing is signed. The approval stays `APPROVED`, so a corrected transaction can be sent. While a transaction is in flight on the approval (`SIGNING` or `SIGNED`), any other transaction is `1409`: one transaction at a time. Asking again for the same transaction returns its signature. Once its batch [settles](/endpoints/approvals-settlement), the approval is `APPROVED` again for the next batch.

One exception: a `SIGNED` transaction that never executed (too large to send, or its relay failed) can be replaced by a transaction at the same Safe nonce, while the Title Safe is still at that nonce and only once the replacement passes every check. A request that fails a check changes nothing. Both transactions stay signed, but they share the nonce, so at most one can ever execute, and whichever does is the one that settles.
