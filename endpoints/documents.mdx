---
title: "Documents"
description: "Retrieve registry documents for a property — title deed, completion certificate, site plan, survey, floor plan."
---

<Note>🔒 **Encrypted payload — response** when a document or its metadata carries owner identity (e.g. the title deed). Purely spatial documents (site plan, survey) may be **TLS only** — the badge is per `docType`, see below.</Note>

```http
GET /property/documents/{plotID}?propertyId={propertyId}&docType=TITLE_DEED
```

One endpoint for every registry document tied to a property. Omit `docType` to list everything available.

## Document level — plot vs property

Registry documents do not all sit at the same level, so `propertyId` is required for some `docType`s and meaningless for others.

| `docType` | Level | `propertyId` |
| --- | --- | --- |
| `TITLE_DEED` | **Property** — one deed per registrable property | **REQUIRED** |
| `COMPLETION_CERT` | **Property** — issued per unit, though a building-wide certificate may also exist | **REQUIRED** |
| `FLOOR_PLAN` | **Property** — the plan of the specific unit | **REQUIRED** |
| `SITE_PLAN` | **Plot** — the parcel's position and boundaries | Not applicable — ignored if sent |
| `SURVEY` | **Plot** — the parcel survey | Not applicable — ignored if sent |

<Warning>
  Requesting `TITLE_DEED` without `propertyId` on a multi-property plot returns a `422` (`errorCode 1422`) rather than an arbitrary deed. Returning "a" deed for a plot is the single most dangerous ambiguity in this integration: VentureOne would validate the wrong title and tokenize a property the issuer does not own.
</Warning>

When `docType` is omitted, the response mixes both levels. Each `Document` carries a `level` and — for property-level documents — its own `propertyId`, so callers can tell which is which. Omitting `propertyId` in that case returns the plot-level documents plus every property's documents.

## Query parameters

<ParamField query="propertyId" type="integer">
  The property whose documents to return. Required for property-level `docType`s (see the table above).
</ParamField>
<ParamField query="docType" type="enum">
  Filter to one type. Omit to return all available documents.
  `TITLE_DEED` · `COMPLETION_CERT` · `SITE_PLAN` · `SURVEY` · `FLOOR_PLAN`
</ParamField>

## Response

| Field | Type | Req. | Use |
| --- | --- | --- | --- |
| `plotID` | int | **REQUIRED** | Echoes the request |
| `documents[]` | Document[] | **REQUIRED** | Available documents — item fields below |
| `status` / `errorCode` | mixed | **REQUIRED** | [Envelope](/introduction/conventions#response-envelope) |

### `Document` item

| Field | Type | Req. | PII | Notes |
| --- | --- | --- | --- | --- |
| `docType` | enum | **REQUIRED** | — | Which document |
| `level` | enum | **REQUIRED** | — | `PLOT` · `PROPERTY` — which entity the document describes |
| `propertyId` | int | CONDITIONAL | — | Present when `level = PROPERTY`; absent for plot-level documents |
| `document` | string | **REQUIRED** | — | PDF/PNG URL or base64 |
| `documentNumber` | string | **REQUIRED** | — | e.g. title-deed number |
| `issueDate` | date | **REQUIRED** | — | ISO-8601 |
| `deedType` | enum | CONDITIONAL | — | Title deed only — `freehold` · `musataha` · `usufruct` · `grant` |
| `ownerNameEn`, `ownerShare` | string / number | CONDITIONAL | ✅ | Title deed only — cross-check ownership |
| `validUntil` | date | OPTIONAL | — | Completion certificate validity |

<Warning>
  When the response includes a title deed (`ownerNameEn` present), the whole body is PII → encrypt as one JWE. A response containing only `SITE_PLAN` / `SURVEY` / `FLOOR_PLAN` has no personal data and may be TLS-only. Because a single call can mix types, default to encrypting the whole response unless ADREC guarantees the filtered set is non-personal.
</Warning>

Maps to → `assets.registry_reference` (the `(plotID, propertyId)` pair plus deed number), and the platform's seeded `asset_documents` of type `title_deed`.
