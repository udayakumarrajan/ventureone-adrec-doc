---
title: "Change Webhooks"
description: "Push notifications for any change to a tokenized property — with a polling fallback."
---

<Note>🔒 **Encrypted payload if it carries personal data · always signed.** A webhook whose `details` include owner/tenant identity is a single JWE; all webhooks are signed regardless.</Note>

```http
POST  {VentureOne callback URL}   ← ADREC calls VentureOne
```

Once a property is tokenized, VentureOne must detect **any** registry change and freeze or act on the live offering. ADREC posts an event to VentureOne's callback URL. 

## Event payload

| Field | Type | Req. | Values |
| --- | --- | --- | --- |
| `eventId` | string | **REQUIRED** | Unique event id (for dedupe) |
| `eventType` | enum | **REQUIRED** | `SALE` · `MORTGAGE` · `BLOCKING` · `OWNERSHIP_CHANGE` · `TENANCY_CHANGE` · `LICENSE_CHANGE` |
| `plotID` | int | **REQUIRED** | Parent plot of the affected property |
| `propertyId` | int | CONDITIONAL | **The affected property.** REQUIRED for every property-scoped event; omitted only for genuinely plot-wide changes (e.g. a boundary or subdivision change) |
| `changedAt` | datetime | **REQUIRED** | ISO-8601 |
| `details` | object | OPTIONAL | Event-specific payload (may carry PII → encrypted) |
| `signature` | string | **REQUIRED** | JWS / HMAC-SHA256 over the event |

<Warning>
  **An event without `propertyId` cannot be routed.** VentureOne freezes an offering on a registry change; if an event only names the plot, every offering on that plot must be frozen and every property re-read to find the one that actually moved. On a subdivided plot that means suspending unrelated live offerings. ADREC must emit `propertyId` for `SALE`, `MORTGAGE`, `BLOCKING`, `OWNERSHIP_CHANGE` and `TENANCY_CHANGE`.

  `LICENSE_CHANGE` concerns a *party*, not a property — it may carry neither identifier, and is matched on the party reference in `details` instead.
</Warning>

## Signature

Every webhook is signed so VentureOne can verify authenticity before acting. Verify the `signature` (JWS) or the `X-Signature` HMAC header **before** processing, and reject stale timestamps to prevent replay. VentureOne responds `2xx` on successful receipt; ADREC retries with backoff otherwise.

## Delivery & acknowledgement

| Concern | Requirement |
| --- | --- |
| Ack | VentureOne returns `2xx` once persisted; non-`2xx` triggers retry |
| Retry | Exponential backoff; `eventId` lets VentureOne dedupe replays |
| Ordering | Not guaranteed — use `changedAt` + `eventId`, re-fetch canonical state on conflict |

## Polling fallback

<Warning>
  If ADREC cannot push webhooks, it **must** expose a polling endpoint so VentureOne can diff on a schedule. This becomes mandatory in that case.
</Warning>

```http
GET /property/changes?since=2026-09-01T00:00:00Z&propertyIds=506999002,71744001
```

Returns the same event objects that would have been pushed, for all supplied properties changed since `since`. Equivalent per-property signal is also available via [Property Status](/endpoints/property-status) (`lastChangedTimestamp`).

| Query param | Type | Req. | Use |
| --- | --- | --- | --- |
| `since` | datetime | **REQUIRED** | ISO-8601 lower bound; omitting it is a `422` validation error |
| `propertyIds` | string | OPTIONAL | Comma-separated `propertyId` values — the **preferred** filter. Returns events for exactly the tokenized properties VentureOne holds |
| `plotIDs` | string | OPTIONAL | Comma-separated plot IDs. Widens to **every** property on those plots, including ones VentureOne has no offering over |

<Note>
  Filter on `propertyIds` in normal operation. `plotIDs` is retained for the case where VentureOne wants to learn about sibling properties on a plot it is invested in — a subdivision or a neighbouring unit's blocking can still be material — but it returns events the platform will mostly discard.

  Supplying both narrows to the intersection. Supplying neither returns events for all tokenized properties.
</Note>
