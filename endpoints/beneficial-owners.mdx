title: "Beneficial Owners — overview"
description: "Keep ADREC's beneficial-ownership register in sync with the cap table as investors subscribe and trade."
---

<Note>🔒 **Encrypted payload — request & response.** Every call carries investor identities → single JWE. Always idempotent and signed.</Note>

As investors subscribe, top up, or exit, VentureOne reports the change to ADREC's beneficial-ownership register. This REST resource covers **add, update, remove, batch sync, and read**. Register release/deregister at offering wind-down is handled by [Registry Transactions](/endpoints/registry-transactions).

<Note>Every mutating call (`POST` / `PATCH` / `DELETE` / `PUT :batchSync`) is a **write**, so it carries an [`Idempotency-Key`](/introduction/conventions#idempotency-writes) alongside the `Authorization` header. The read (`GET`) needs only `Authorization`.</Note>

<Info>
  The platform holds only limited investor identity — `full_name`, `email`, `wallet_address`, and KYC/AML/eligibility status (no Emirates ID column). Holdings are derived from `subscriptions.token_quantity` and the cap table. The `BeneficialOwner` schema below reflects what VentureOne can actually supply; confirm ADREC's required identity granularity.
</Info>

## The `BeneficialOwner` object

Shared by every operation on this resource.

| Field | Type | Req. | PII | Maps to |
| --- | --- | --- | --- | --- |
| `beneficialOwnerId` | string | CONDITIONAL | — | ADREC's id (absent on create) |
| `offeringReference` | string | **REQUIRED** | — | `VO-OFF-…` → the SPV/deed the register attaches to |
| `plotID` | int | **REQUIRED** | — | The tokenized property |
| `fullNameEn` | string | **REQUIRED** | ✅ | `investors.full_name` |
| `email` | string | OPTIONAL | ✅ | `investors.email` |
| `nationality` | string | OPTIONAL | ✅ | If ADREC requires it |
| `holdingPercentage` | number | **REQUIRED** | — | Share of the offering |
| `tokenQuantity` | number | **REQUIRED** | — | `subscriptions.token_quantity` |
| `walletAddress` | string | OPTIONAL | — | `investors.wallet_address` |
| `effectiveDate` | date | **REQUIRED** | — | When the holding took effect |
