---
title: "Service Charges"
description: "Community / service-charge status for net-income modelling."
---

<Note>**TLS only.** Property-level financial data — no personal data.</Note>

```http
GET /property/service-charges/{plotID}?propertyId={propertyId}
```

Returns the service-charge / community-fee position for a property, an input to net-distributable-income modelling. Feeds the platform's `property_revenue_reports.service_charges`.

Service charges are levied **per property** — they scale with unit area, and arrears sit against the individual owner, not the plot. Omit `propertyId` to return the position for every property on the plot.

## Query parameters

| Param | Type | Req. | Use |
| --- | --- | --- | --- |
| `propertyId` | int | OPTIONAL | Narrow to one property. Omit for **every** property on the plot |

## Response (root)

| Field | Type | Req. | Maps to / use |
| --- | --- | --- | --- |
| `plotID` | int | **REQUIRED** | Echoes the request |
| `properties[]` | ServiceCharge[] | **REQUIRED** | One item per property in scope — item fields below |
| `managementCompanyEn` | string | OPTIONAL | OA / management company — usually plot- or building-level |
| `status` / `errorCode` | mixed | **REQUIRED** | [Envelope](/introduction/conventions#response-envelope) |

### `ServiceCharge` item

| Field | Type | Req. | Maps to / use |
| --- | --- | --- | --- |
| `propertyId` | int | **REQUIRED** | Which property this charge applies to |
| `annualServiceCharge` | number | **REQUIRED** | Annual community/service fee → `property_revenue_reports.service_charges` |
| `ratePerSqm` | number | OPTIONAL | Basis of the charge |
| `currency` | string | **REQUIRED** | `AED` |
| `outstandingBalance` | number | **REQUIRED** | Arrears → net-income risk. **Per property** — one unit in arrears does not encumber its neighbours |
| `paidUntil` | date | OPTIONAL | Coverage period |

<Warning>
  Do not model `outstandingBalance` at plot level. Arrears follow the property's owner, and an offering must only be charged for the property it actually holds.
</Warning>
