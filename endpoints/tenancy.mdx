---
title: "Tenancy & Occupancy"
description: "Tawtheeq tenancy contracts and occupancy status — the inputs to revenue modelling."
---

<Note>🔒 **Encrypted payload — response.** Tenant identities are PII → single JWE. If VentureOne only needs occupancy aggregates, request the non-personal projection (below) for a TLS-only response.</Note>

```http
GET /tenancy/{plotID}?propertyId={propertyId}&view=full
```

Returns tenancy contracts (Tawtheeq, run by ADREC) and current occupancy for a property. This feeds the platform's `tenant_lease_summaries` and revenue projections.

A lease is signed over a **property**, not a plot: units on one plot have different tenants, rents and lease dates, and one can be occupied while another is vacant. Omit `propertyId` to return every property's tenancy on the plot.

## Query parameters

<ParamField query="propertyId" type="integer">
  Narrow to one property on this plot. Omit to return a tenancy record per property.
</ParamField>
<ParamField query="view" type="enum" default="full">
  `full` returns contract detail incl. tenant identity (PII, encrypted). `occupancy` returns only non-personal occupancy aggregates (TLS-only).
</ParamField>

## Response (root)

| Field | Type | Req. | Maps to / use |
| --- | --- | --- | --- |
| `plotID` | int | **REQUIRED** | Echoes the request |
| `properties[]` | PropertyTenancy[] | **REQUIRED** | One item per property in scope — item fields below |
| `status` / `errorCode` | mixed | **REQUIRED** | [Envelope](/introduction/conventions#response-envelope) |

### `PropertyTenancy` item

| Field | Type | Req. | Maps to / use |
| --- | --- | --- | --- |
| `propertyId` | int | **REQUIRED** | Which property this tenancy describes |
| `occupancyStatus` | enum | **REQUIRED** | `OCCUPIED` · `VACANT` · `NOTICE_GIVEN` · `RENEWAL_PENDING` · `EXPIRED` → `tenant_lease_summaries.occupancy_status` |
| `contracts[]` | TenancyContract[] | CONDITIONAL | Present in `view=full` — item fields below |

<Warning>
  Occupancy must not be aggregated to plot level. A plot reading `OCCUPIED` because one of four units is let would inflate the revenue model for an offering over a vacant unit.
</Warning>

### `TenancyContract` item

| Field | Type | Req. | PII | Maps to |
| --- | --- | --- | --- | --- |
| `contractNumber` | string | **REQUIRED** | — | `tenant_lease_summaries.tenant_reference` |
| `propertyId` | int | **REQUIRED** | — | The leased property — echoes the parent item |
| `tenantNameEn` | string | **REQUIRED** | ✅ | Tenant identity |
| `leaseStartDate` / `leaseEndDate` | date | **REQUIRED** | — | `lease_start` / `lease_end` |
| `annualRent` | number | **REQUIRED** | — | `rent_amount` |
| `paymentFrequency` | enum | **REQUIRED** | — | `MONTHLY·QUARTERLY·SEMI_ANNUAL·ANNUAL` → `payment_frequency` |
| `renewalStatus` | object | OPTIONAL | — | `renewal_status` · coded value `{ constant, lookupNameEn, lookupNameAr }` |

<Info>
  **Tenancy write (step 26)** — whether VentureOne must *register* contracts (`POST /tenancy`) or only read them is an [open gap](/introduction/scope-and-reconciliation#gaps-items-to-confirm-with-adrec). Documented as read-only until ADREC confirms. If the write is enabled, it is a state-changing operation and must carry an `Idempotency-Key` header (generated by the upstream VentureOne application) per [Idempotency](/introduction/conventions#idempotency-writes), and its body must name the `propertyId` being let — not just the `plotID`.
</Info>
